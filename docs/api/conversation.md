# conversation


## `text_message`

构造显式角色和内容段的文本消息，保留 Unicode 与换行。允许空助手文本作为流式输出起点，但限制单段长度。

## `audio_message`

把音频嵌入用户消息，并可附带提问文本。WAV 记录采样率和声道，不依赖临时文件路径；此格式不是任何外部厂商的专有协议。

## `validate_message`

完整校验消息、内容段与音频载荷，拒绝未知字段和不支持的音频角色。输出深复制，调用者不能借嵌套引用修改历史消息。

## `validate_conversation`

对话可有一个前置系统消息，随后用户与助手轮次交替。允许最后一个用户请求尚未获得回复，但拒绝中途插入系统消息。

## `append_message`

以复制方式追加消息，统一校验轮次顺序和内容模式。拒绝路径以及成功后的嵌套修改都不会影响原始历史。

## `replace_transcript`

修订用户转录文本时保留原音频段，移除旧文本后附加新文本。可用于流式识别的整句修订，而不是把修正错误地追加到旧句尾。

## `apply_delta`

按连续修订号替换完整转录文本，拒绝跳号、重复号和终结后的更新。更新不会修改输入状态，便于日志重放与错误恢复。

## `truncate_context`

按用户发起的完整轮次组保留最近上下文，避免留下没有对应用户请求的助手消息。前置系统上下文和最新未完成请求都会保留。
